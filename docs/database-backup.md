# Локальная копия прикладной базы перед выпуском

12 октября 2026 в панели действующего проекта Supabase awkjrolplhvrscuqqive подтверждено: Free Plan does not include project backups. Платный тариф не включался. Connect → Direct → Session pooler показывает бесплатное IPv4-подключение aws-1-ap-south-1.pooler.supabase.com:5432, пользователь postgres.awkjrolplhvrscuqqive, база postgres.

Подготовлен Windows-скрипт scripts/backup-application-database.ps1. Он использует PostgreSQL 17.11, сохраняет согласованный архив двух схем **public и supabase_migrations** с данными, функциями, последовательностями, RLS и правами. Это область изменений подготовленного выпуска, а не полная копия Supabase-проекта. Auth, Storage, сами загруженные файлы, глобальные роли, ключ шифрования Vault, переменные Vercel и настройки Telegram сюда не входят. Существующие файлы Storage выпуск не переносит и не удаляет; для восстановления всего проекта нужен их отдельный план.

## Запуск на этом компьютере

Откройте PowerShell 7 в папке ISHDASIZ NEW:

```powershell
npm run backup:database
```

Появится скрытый запрос **существующего пароля базы Supabase**. Это не API-ключ, не пароль пользователя сайта и не пароль аккаунта Supabase. Не вставляйте пароль в команду, чат, SQL Editor или Git. Скрипт передаёт его только дочернему процессу PostgreSQL через окружение, подключается по TLS к указанному выше фиксированному серверу и не сохраняет пароль на диск. Если пароль неизвестен, остановитесь на запросе: скрипт сам пароль не сбрасывает.

Скрипт создаёт новую уникальную папку private-backups/<время>-<UUID> с доступом только для текущего Windows-пользователя. Эта папка исключена из Git. В ней будут application.dump, manifest.json и закрытые журналы ошибок. Каждая новая копия получает отдельную папку; старые копии не перезаписываются. В архиве находятся личные данные и хеши паролей приложения — не публикуйте его и не помещайте в обычную папку релиза.

Соединение задаётся параметрами без пароля в командной строке. Наследованные PG-переменные удаляются из окружения дочерних процессов. Перед копированием проверяются версия сервера, роль и обязательные таблицы. Для соединения включён default_transaction_read_only; pg_dump читает обе схемы в одном снимке и останавливается при ошибке блокировки/доступа. Частичный результат не получает manifest.json: вместо него появляется incomplete.json.

После копирования скрипт проверяет состав архива, читает все его блоки через pg_restore без подключения к базе и записывает SHA-256. archiveFullyReadable=true означает корректное чтение архива. **restorationVerified=false остаётся до настоящей проверки восстановления конкретной копии**. Нельзя считать одну проверку заголовка или контрольной суммы доказательством восстановления.

## Что проверено локально

```powershell
npm run test:backup
```

Проверка запускает временный PostgreSQL только на 127.0.0.1 со случайным портом. Создаёт синтетические таблицы users/jobs/resumes и историю миграций, копирует их тем же скриптом, восстанавливает в отдельную пустую тестовую базу и сравнивает данные, RU/UZ-текст, NULL, последовательность, функцию, RLS, политику и права. Проверяется отказ для повреждённого архива и отсутствующей таблицы, а также ограничения доступа к папке. После проверки тестовый сервер останавливается; файлы доказательств остаются в .tmp и private-backups. Рабочий Supabase в этой проверке не вызывается.

Реальное восстановление архива рабочей базы ещё не проверено. Для него нужна отдельная совместимая тестовая база с нужными ролями и расширениями; нельзя запускать восстановление на рабочем адресе. Подготовленный helper намеренно не содержит команд удаления схем или восстановления в Production. При восстановлении прикладных схем нужно отдельно согласовать текущие глобальные роли, владельцев объектов, зависимости от управляемых схем Supabase и состояние файлов Storage. Откат старой версии сайта требует совместимой схемы.

## Происхождение инструментов

На этом компьютере клиент и средства локальной проверки распакованы в .tmp/postgres-client-17.11/pgsql из официального EDB ZIP, на который ссылается [PostgreSQL Windows Downloads](https://www.postgresql.org/download/windows/). [Список EDB](https://www.enterprisedb.com/download-postgresql-binaries), выбранный Windows x86-64 17.11: https://sbp.enterprisedb.com/getfile.jsp?fileid=1260616. Использована переносимая версия; служба Windows не устанавливалась. Версии pg_dump и pg_restore проверены: 17.11. source.json содержит источник и локально вычисленный SHA-256 архива. Этот hash и CRC ZIP проверяют полученный файл, но не являются независимой подписью поставщика; pg_dump.exe не имеет Authenticode-подписи.

Если временные инструменты удалены, передайте -PgBin с путём к штатному PostgreSQL 17+; для test:backup дополнительно нужны initdb, pg_ctl, postgres и их штатные share/lib. На Linux для восстановления используйте штатные инструменты PostgreSQL и отдельно проверенный порядок; этот Windows-helper там не запускается.

Документация: [Supabase — копирование через Session pooler и история миграций](https://supabase.com/docs/guides/platform/migrating-within-supabase/backup-restore), [pg_dump — согласованный архив](https://www.postgresql.org/docs/17/app-pgdump.html), [pg_restore](https://www.postgresql.org/docs/17/app-pgrestore.html).
