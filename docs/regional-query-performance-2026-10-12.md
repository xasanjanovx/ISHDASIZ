# Поиск вакансий по регионам: состояние 13 октября 2026

В Production применена миграция `20261012150000_regional_query_performance.sql`; подтверждены 60 версий истории, корректное определение функции и прежнее расписание импорта. Повторять первые 41 файл нельзя. Локальное ускорение этой функции оказалось недостаточным: после применения живые запросы точного подсчёта по регионам 8, 9 и 10 по-прежнему завершились PostgreSQL 57014. PR #6 не объединён; успешная Preview-сборка не подтверждает исправление каталога.

Последовательная диагностика показала: общий доступный подсчёт и физический регион работают; выборка региональных/удалённых вакансий без точного подсчёта работает; точный подсчёт с вычисляемым форматом работы зависает даже под service_role. Публичный лимит 3 секунды сохраняется.

Новая миграция `20261013100000_catalog_work_mode_cache.sql` подготовлена, но ещё не применена. Нормализованный формат сохраняется в отдельном столбце при записи. Временный GENERATED STORED столбец выполняет начальное заполнение без прикладных UPDATE-триггеров, затем DROP EXPRESSION сохраняет значения как обычный столбец. Первый BEFORE-триггер пересчитывает значение из исходных полей и перезаписывает попытки подделать кэш. Скалярный SQL getter под прежним именем вычисляемого поля позволяет планировщику использовать обычный частичный индекс. Приоритеты work_mode, необязательного work_format, raw_source_json и employment_type сохранены; неизвестный явный формат по-прежнему блокирует запасной remote.

На изолированном PostgreSQL 17 из настоящего прикладного архива исходные поля и прежний результат формата работы совпали для всех 40 812 вакансий, все 14 региональных подсчётов сохранили точный результат. Планировщик без принудительных настроек использовал новый индекс. Все 14 запросов под anon прошли с лимитом 3 секунды за примерно 5–11 мс каждый. Повторное применение сохранило все исходные поля. Это локальная репетиция; фактическую работу PostgREST и всех 14 фильтров требуется подтвердить после переноса.
